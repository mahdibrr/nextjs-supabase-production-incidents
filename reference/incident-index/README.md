# Incident Index: Next.js + Supabase + Stripe Production Problems and Fixes

Last verified: 2026-07-19

> This is the numbered catalog mapping each incident to a reusable asset in this repo. For a broader symptom-organized debugging reference with links to the official docs, see the [Symptom Reference](../../content/incidents/README.md).

| Problem | Stack (Next.js / Supabase / Stripe) | Root Cause | Fix | Reference Asset Link |
| --- | --- | --- | --- | --- |
| INC-001: `cookies() should be awaited` runtime warning in App Router | Next.js | Reading cookies in contexts that became async in newer runtime behavior. | Use `await cookies()` where required and isolate cookie access in server boundaries. | [Server Actions debugging matrix](../playbooks/server-actions-debugging-matrix.md) |
| INC-002: Supabase returns empty array for existing rows | Supabase | RLS enabled but no matching `select` policy for authenticated role. | Add scoped `select` policies and test with anon/authenticated clients. | [RLS empty-array postmortem](../playbooks/rls-empty-array-postmortem.md), [RLS audit SQL](../sql/rls-audit.sql), [RLS pgTAP example](../../examples/rls-pgtap/README.md) |
| INC-003: Infinite recursion detected in policy | Supabase | Policy references the same table recursively through nested `exists` logic. | Split policy concerns, move recursion checks to helper tables/views, and index predicates. | [RLS audit SQL](../sql/rls-audit.sql), [RLS pgTAP example](../../examples/rls-pgtap/README.md) |
| INC-004: OAuth callback loops to login in App Router | Next.js + Supabase | Middleware matcher protects `/auth/callback` or login path. | Exclude callback/login routes from protected matcher and verify cookie write path. | [Server Actions debugging matrix](../playbooks/server-actions-debugging-matrix.md) |
| INC-005: Session disappears after refresh in SSR | Next.js + Supabase | Server-side cookie refresh path not wired or wrong domain settings. | Validate SSR client cookie flow and domain attributes in prod/preview. | [Server Actions debugging matrix](../playbooks/server-actions-debugging-matrix.md) |
| INC-006: Webhook signature verification failed | Stripe | Wrong endpoint secret, transformed body, or environment mismatch. | Verify raw body handling and use environment-scoped webhook secret. | [Stripe webhook state machine](../diagrams/stripe-webhook-state-machine.md), [Stripe webhook idempotency template](../templates/stripe-webhook-idempotency-template.sql), [Stripe webhook example](../../examples/stripe-webhook-idempotency/README.md) |
| INC-007: Duplicate subscription rows from retries | Stripe + Supabase | No idempotency store for webhook event IDs. | Persist event IDs and reject duplicates before state mutation. | [Stripe webhook state machine](../diagrams/stripe-webhook-state-machine.md), [Stripe webhook idempotency template](../templates/stripe-webhook-idempotency-template.sql), [Stripe webhook example](../../examples/stripe-webhook-idempotency/README.md) |
| INC-008: `revalidatePath` runs but stale data persists | Next.js + Supabase | Mutation path and revalidated path/tag do not match data boundary. | Revalidate exact route/tag tied to cached fetch key and verify with server logs. | [revalidate stale postmortem](../playbooks/revalidate-stale-postmortem.md), [Server Actions debugging matrix](../playbooks/server-actions-debugging-matrix.md), [Next.js 15 example](../../examples/nextjs15-cache-and-params/README.md) |
| INC-009: Migration succeeds in staging and fails in prod | Supabase + PostgreSQL | Hidden assumptions on data shape, extension availability, or locks. | Use preflight checks, lock-aware migrations, and rollback script rehearsals. | [Zero-downtime rollout checklist](../checklists/zero-downtime-rollout-checklist.md) |
| INC-010: Rollback blocks writes for too long | Supabase + PostgreSQL | Rollback plan missing lock budget and phased fallback strategy. | Define lock timeout budgets and run tested rollback playbook. | [Migration rollback playbook](../playbooks/migration-rollback-playbook.md) |
| INC-011: Server Actions write succeeds but UI reads old state | Next.js | Mixed static and dynamic rendering boundaries with stale cache tags. | Enforce dynamic boundaries for user-scoped data and revalidate targeted tags. | [Server Actions debugging matrix](../playbooks/server-actions-debugging-matrix.md), [Next.js 15 example](../../examples/nextjs15-cache-and-params/README.md) |
| INC-012: Edge Function webhook processing times out | Supabase + Stripe | Long-running logic and no queue handoff for retries. | Use queue handoff pattern and keep edge handlers idempotent and short. | [Stripe webhook idempotency template](../templates/stripe-webhook-idempotency-template.sql), [Stripe webhook example](../../examples/stripe-webhook-idempotency/README.md) |
| INC-013: pgvector query latency spikes after index changes | Supabase + PostgreSQL | Missing maintenance/reindex strategy and inconsistent embedding dimensions. | Validate dimensions, inspect plans, and benchmark before deploy. | [pgvector benchmark template](../templates/pgvector-benchmark-template.md) |
| INC-014: Middleware auth breaks static assets | Next.js | Matcher scope accidentally includes `_next/static` or image paths. | Narrow matcher and explicitly exclude static/runtime paths. | [Server Actions debugging matrix](../playbooks/server-actions-debugging-matrix.md) |
| INC-015: RLS policy slows API to unusable latency | Supabase + PostgreSQL | Policy predicates missing supporting indexes on tenant/user columns. | Add composite indexes and validate with `EXPLAIN ANALYZE`. | [RLS audit SQL](../sql/rls-audit.sql), [RLS pgTAP example](../../examples/rls-pgtap/README.md) |
| INC-016: Webhook returns 200 OK but business state is wrong | Stripe + Supabase | Event-ID dedup passes, but side effects are not independently idempotent. The failure is two-sided: marking the event processed before its side effects commit produces duplicates, while a first attempt that fails after recording the event ID makes retries skip it as already seen — silently dropping the event. | Track processing state (`received` → `processing` → `processed` / `failed`), not just "seen"; give each side effect its own idempotency key; return 200 only after side effects commit and non-2xx for unfinished work so Stripe retries; put a lease and attempts cap on `processing`; reconcile expired or missed events from the Stripe API. | [Stripe webhook state machine](../diagrams/stripe-webhook-state-machine.md), [Stripe webhook idempotency template](../templates/stripe-webhook-idempotency-template.sql), [Stripe webhook test plan](../playbooks/stripe-webhook-test-plan.md), [Stripe webhook example](../../examples/stripe-webhook-idempotency/README.md) |
| INC-017: Vercel serverless / Supavisor Postgres connection pool exhaustion | Next.js + Supabase | Serverless fan-out opens more Postgres connections than `max_connections` or the Supavisor pool allows; direct-vs-pooler string mixup and module-scope clients that leak on suspension compound it. | Use the transaction pooler (port 6543) for runtime and direct (5432) only for migrations; set `prepare: false`/`?pgbouncer=true`; avoid module-scope clients; size the pool and load-test in CI. | [Connection pool exhaustion postmortem](../playbooks/connection-pool-exhaustion-postmortem.md) |
| INC-018: ORM (Prisma/Drizzle) bypassing Supabase RLS via service_role | Supabase + Prisma/Drizzle | ORM connects with `service_role` (BYPASSRLS) or a fixed role, so policies are never evaluated against the user's JWT. | Use `supabase-js` for tenant-scoped queries (carries the JWT), or set the Postgres role + `request.jwt.claims` per request, or make `service_role`+app-authz a deliberate choice. | [ORM bypassing RLS postmortem](../playbooks/orm-bypassing-rls-postmortem.md), [RLS pgTAP example](../../examples/rls-pgtap/README.md) |
| INC-019: Supabase Realtime stale / missing / duplicated updates after tab suspension | Supabase + Next.js | Background-tab throttling freezes Realtime frames, and Realtime does not backfill changes missed while disconnected. | Resync on every (re)subscribe and on `visibilitychange` to visible via a watermarked catch-up query, dedupe by PK + `commit_timestamp`, and run heartbeats in a Web Worker. | [Realtime tab-suspension postmortem](../playbooks/realtime-tab-suspension-postmortem.md) |
| INC-020: Next.js 15 made `params`/`searchParams` async (Promise) | Next.js | Next.js 15 changed `params`/`searchParams` props of pages, layouts, route handlers, and `generateMetadata` to Promises; sync access reads a property off a Promise. | `const { id } = await params;` in every server entry; run the `next-async-request-api` codemod; client components use React 19's `use()` hook. | [Next.js 15 async params postmortem](../playbooks/nextjs15-async-params-postmortem.md), [Next.js 15 example](../../examples/nextjs15-cache-and-params/README.md) |
| INC-021: Storage uploads succeed but private files leak (or uploads 403) | Supabase | Public bucket or unscoped `storage.objects` `select` policy bypasses owner scoping; missing `update` policy makes upserts 403. | Make the bucket private, scope all four object policies by `owner_id`/`(storage.foldername(name))[1] = auth.uid()`, issue short-TTL signed URLs server-side, use `upsert: true`. | [Storage RLS upload postmortem](../playbooks/storage-rls-upload-postmortem.md), [RLS pgTAP example](../../examples/rls-pgtap/README.md) |
| INC-022: A user is signed in as someone else (cached `Set-Cookie` or shared server client) | Next.js + Supabase | A session refresh writes the new JWT in `Set-Cookie`; ISR or a CDN caches that response and serves it to another user, or a module-scope Supabase client is reused across requests on warm instances. | No ISR on routes where a session can refresh; apply the cache headers `@supabase/ssr` ≥ 0.10.0 passes to `setAll` (or `Cache-Control: private, no-store`); verify the CDN honors it; create the server client per request. | [Session leak postmortem](../playbooks/session-leak-cached-set-cookie-postmortem.md) |
| INC-023: Server code authorizes with `getSession()` | Next.js + Supabase | `getSession()` returns the session from the cookie without revalidating it, so its embedded `user` object is client-controlled. | Use `getClaims()` for server-side identity (local on asymmetric keys, an Auth-server call on symmetric secrets); `getUser()` where revoked sessions must be rejected. | [getSession server-trust postmortem](../playbooks/getsession-server-trust-postmortem.md) |
| INC-024: `FATAL: Tenant or user not found` after switching to the pooler | Next.js + Supabase | Shared-pooler username lacks `.<project-ref>`, or the pooler host was typed (`aws-0-…`) instead of copied. Not a saturated pool. | Copy the whole string from the dashboard Connect dialog and replace only the password; plain `postgres` stays on the direct/dedicated host. | [Pooler tenant-not-found postmortem](../playbooks/pooler-tenant-not-found-postmortem.md) |
